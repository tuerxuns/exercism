Go Organization

Packages, Comments & Exported Names

Understand modularity through packages, document code with comments, and control access visibility via capitalization.

1. Packages in Go

Every Go file must declare which package it belongs to. Packages group files that belong to the same directory and share a common namespace. For example:

package weather

All files in the same directory must use the exact same package name. The package name is used by other parts of the program to access functions, variables, or custom types defined in that package.

2. Documenting with Comments

Go supports standard commenting conventions to describe code logic, which can be compiled into documentation automatically using tools like godoc:

  • Line Comments (//): Single-line descriptions. Used for short inline comments or documenting function signatures. 
    // CurrentCondition stores the weather condition string.
var CurrentCondition string
  • Block Comments (/* ... */): Multi-line descriptions. Often used for package-level documentation at the very top of a package file.

3. Exported Names

In Go, visibility is controlled entirely by the capitalization of the identifier's first character:

  • Exported (Public): If the identifier starts with a capital letter, it is public and can be accessed outside the package. 
    func Forecast(city string) string // Exported function
  • Unexported (Private): If it starts with a lowercase letter, it is private and only visible inside its package. 
    var currentCondition string // Unexported variable

Self-Check Quiz

1. Can files in the same directory declare different package names?
🎉 Correct! All files in a directory are compiled together as a single package and must share the same package declaration.
❌ Not quite. Go enforces directory-level modularity. Every file in the same folder must declare the exact same package name.
2. Which of the following defines an exported variable named "temperature"?
🎉 Correct! Capitalizing the first character (Temperature) makes it public (exported) outside the package.
❌ Oops! Go does not use keywords like public or export. It relies entirely on capitalization to control visibility.
3. What is the standard comment syntax for package-level multiline documentation in Go?
🎉 Correct! Block comments (/* ... */) are typically used for package documentation headers.
❌ Not quite. # is not a valid comment character in Go. Go uses // for line comments and /* */ for block comments.

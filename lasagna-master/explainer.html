Master function parameters, multiple return values, and pass-by-value vs pass-by-reference with slices in Go.

1. Function Parameters & Grouped Types

Every function parameter in Go must have an explicit type — there is no inference for parameters. When two or more adjacent parameters share the same type, you can group them with a single type declaration:

Verbose style

func Greet(first string, last string) string {
    return first + " " + last
}

Grouped style

func Greet(first, last string) string {
    return first + " " + last
}
💡 No default values in Go

Go functions have no default parameter values. If you want a "default" behaviour, check for a zero value inside the function body — e.g. if an int argument is 0, substitute your own default.

2. Multiple Return Values

Go functions can return more than one value — a feature used heavily in idiomatic Go, especially for returning a result alongside an error. Multiple return types are wrapped in parentheses:

func Quantities(layers []string) (int, float64) {
    // returns noodles (int) and sauce (float64)
    return noodles, sauce
}

// Calling it — capture both return values:
noodles, sauce := Quantities(layers)

If you only need one of the return values, discard the other with _:

noodles, _ := Quantities(layers) // ignore sauce
⚠️ Named return values

Go also supports named return values. You name the return variables in the signature and use a bare return at the end. This can improve readability for complex functions but should be used sparingly as it can reduce clarity.

func Quantities(layers []string) (noodles int, sauce float64) {
    // noodles and sauce are pre-declared
    return // returns noodles and sauce implicitly
}

3. Pass-by-Value vs Pass-by-Reference

In Go, all arguments are passed by value — a copy is made. For primitive types like int or string, this means the original is never changed inside the function:

func Double(n int) int {
    n = n * 2
    return n
}

x := 5
result := Double(x)
// result == 10, x is still 5

Slices are different

Slices, maps, and channels are reference types. When you pass a slice to a function, you're passing a reference to the underlying array — not a full copy. Modifications inside the function affect the original:

func SetFirst(s []string, val string) {
    s[0] = val // modifies the original!
}

list := []string{"a", "b", "c"}
SetFirst(list, "z")
// list is now ["z", "b", "c"]
💡 When you need a true copy

To avoid mutating the original slice, make a copy first using append([]T(nil), original...) or the built-in copy() function before modifying it.

Self-Check Quiz

1. A function receives an avgTime int parameter. If no time is provided by the caller, avgTime will be 0. How should you handle this inside the function?
🎉 Correct! Go has no default parameter values, so you check for the zero value (0 for int) inside the function body and substitute your default manually.
❌ Go does not support default parameter values. The idiomatic solution is to check for the zero value of the type and apply the default yourself inside the function.
2. A function returns (int, float64). How do you capture only the float64 return value and discard the int?
🎉 Correct! The blank identifier _ discards an unwanted return value. You must always account for every return value — you can't simply ignore one without _.
❌ Go requires you to handle every return value. Use _ to explicitly discard the ones you don't need: _, result := myFunc().
3. You pass a []string slice to a function and modify an element inside. What happens to the original slice?
🎉 Correct! Slices hold a reference to an underlying array. Passing a slice to a function passes that reference, so any element modifications affect the original — no explicit pointer needed.
❌ Slices are reference types in Go. Even without a * pointer, modifying elements of a slice inside a function affects the original slice the caller holds.
